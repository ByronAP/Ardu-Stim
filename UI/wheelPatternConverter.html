About Run-Length Encoding (RLE)

Run-Length Encoding is a simple compression technique that replaces repeated values with a value and a count of repetitions.

Basic RLE Format

The basic RLE format used here is:

value1, count1, value2, count2, ...

Which means "value1 repeated count1 times, followed by value2 repeated count2 times, etc."

Optimized RLE Format

The optimized format looks for repeating patterns and encodes them as:

pattern_length, [pattern values], repeat_count, [more patterns]...

For example, if the pattern "1,0" repeats 10 times, it would be encoded as:

2, 1,0, 10, [rest of the data]

Decoder Code

Here's the C/C++ code you'll need to add to your ArduStim project to read the RLE format:

// For basic RLE format uint8_t getEdgeState(const unsigned char* pattern, uint16_t index) { uint16_t pos = 0; uint16_t currentIndex = 0; while (currentIndex <= index) { uint8_t value = pgm_read_byte(&pattern[pos++]); uint8_t count = pgm_read_byte(&pattern[pos++]); if (currentIndex + count > index) { // Found the segment containing our index return value; } currentIndex += count; } return 0; // Default value } // For optimized RLE format uint8_t getEdgeStateOptimized(const unsigned char* pattern, uint16_t index) { uint16_t pos = 0; uint16_t currentIndex = 0; while (currentIndex <= index) { uint8_t patternLength = pgm_read_byte(&pattern[pos++]); // If pattern length is 0, we've reached the end if (patternLength == 0) break; // Store the pattern uint8_t patternValues[16]; // Max pattern length for (uint8_t i = 0; i < patternLength; i++) { patternValues[i] = pgm_read_byte(&pattern[pos++]); } uint8_t repeatCount = pgm_read_byte(&pattern[pos++]); uint16_t totalEntries = patternLength * repeatCount; if (currentIndex + totalEntries > index) { // Our target index is within this repeated pattern uint16_t localIndex = (index - currentIndex) % patternLength; return patternValues[localIndex]; } currentIndex += totalEntries; } return 0; // Default value }

Memory Savings

The RLE format typically reduces the wheel pattern size by 50-80% depending on the pattern complexity. The optimized format can achieve even better compression for highly repetitive patterns.
